## 2026-03-03 — Fix integration test: ALPN mismatch in p2panda-blobs

Root cause: `endpoint.accept()` in p2panda-net hashes the ALPN with the network ID, but
iroh-blobs' `Downloader` hardcodes `iroh_blobs::ALPN` when connecting. The server (Penguin)
only accepted the hashed ALPN, causing TLS handshake failure on every download attempt.

Fix: Added `RegisterRawProtocol` variant to `ToIrohEndpoint` and `accept_raw()` method to
`p2panda-net::Endpoint`. This registers a protocol under its raw ALPN without network-ID
hashing. Changed `Blobs::new` to use `endpoint.accept_raw(iroh_blobs::ALPN, ...)` so both
connecting (downloader) and accepting (BlobsProtocol) sides use the same ALPN.

Files changed:
- `p2panda-net/src/iroh_endpoint/actors/endpoint.rs` — new `RegisterRawProtocol` variant + handler
- `p2panda-net/src/iroh_endpoint/api.rs` — new `accept_raw()` method
- `p2panda-blobs/src/blobs.rs` — use `accept_raw` instead of `accept`

`cargo test -p p2panda-blobs` and `cargo test -p p2panda-net` both pass cleanly.

## 2026-03-03 — Add p2panda-file-sharing: blob+gossip file transfer app

Built `p2panda-file-sharing` (`p2panda-test-claude/`) from scratch using the correct
gossip + blobs architecture (replacing the prior LogSync-based prototype).

Architecture:
- `send --topic <name> <file>`: imports file into iroh-blobs via `Blobs::add_slice`,
  prints node ID and content hash, then gossip-announces a `BlobAnnouncement`
  (32-byte hash || UTF-8 filename) on the derived topic.
- `receive --topic <name> [--output-dir] [--peer]`: subscribes to gossip, decodes
  announcements, calls `Blobs::download(hash)`, reads bytes with `get_bytes`, and
  writes to the output directory preserving the original filename.
- Topic ID derived from user string: `Hash::new(topic.as_bytes()).into::<TopicId>()`.
- mDNS active discovery for LAN peers; `--peer` flag wired for future relay use.

Workspace changes:
- Added `p2panda-test-claude` to workspace `members`.
- Renamed package `p2panda-file-sharing` and switched deps to local path refs.
- Replaced old test (`tests/transfer.rs`) with a two-node gossip+blob integration test.

both pass cleanly. Unit tests (protocol roundtrip) pass.

## 2026-03-03 — Implement --peer / --relay-url / --passive-mdns CLI flags (PRD task 5)

Completed the implementation of the three missing CLI features needed for relay-based
peer discovery in `p2panda-file-sharing`:

1. `--peer <node_id>`: previously logged but fully ignored.  Now parses the hex
   Ed25519 public key, constructs `NodeInfo::new(node_id).bootstrap()`, and inserts
   it into the node's address book.  When `--peer` is given mDNS is automatically
   switched to passive mode so relay is the primary connection mechanism.

2. `--relay-url <url>`: new flag on both `send` and `receive`.  Parses an
   `iroh::RelayUrl` and passes it to the `Endpoint::builder(...).relay_url(...)`.
   Without this the iroh endpoint has no relay map and cannot use relay transport.

3. `--passive-mdns`: new flag on both `send` and `receive`.  Switches mDNS from
   `Active` to `Passive` mode so no unsolicited mDNS announcements are made, forcing
   connections to go through the configured relay (or explicit peer addresses).

Files changed:
- `p2panda-test-claude/src/node.rs` — `NodeOptions` struct + derive Default;
  `FileSharingNode::new` accepts `NodeOptions` instead of no args.
- `p2panda-test-claude/src/main.rs` — parse `--peer`, `--relay-url`, `--passive-mdns`
  for both subcommands; insert bootstrap `NodeInfo` when `--peer` is present.

All 5 tests continue to pass (`cargo test -p p2panda-file-sharing`).
PRD task 5 remains `passes:false`: the end-to-end relay test requires a live relay
server which is not available in this environment.

## 2026-03-03 — Integration test: --peer flag with passive mDNS (PRD task 5)

Added `test_peer_flag_passive_mdns_transfer` to `p2panda-test-claude/tests/transfer.rs`.

Both nodes use passive mDNS so no automatic discovery occurs. Node B bootstraps
with Node A's directly-fetched bound socket address via `iroh_ep.bound_sockets()`,
then replaces `0.0.0.0` with `127.0.0.1` (loopback) to enable direct connection.
This simulates the `--peer <node_id>` CLI flow: a relay server normally provides
the peer's address; the test uses the actual bound address instead to stay
self-contained (no external relay server required).

Key steps:
- Get inner iroh endpoint: `node_a.endpoint.endpoint().await`
- Call `bound_sockets()` and find the IPv4 socket
- Construct `EndpointAddr` with loopback IP and actual port
- Insert `NodeInfo::from(endpoint_addr).bootstrap()` into Node B's address book
- Gossip + blob transfer verifies the end-to-end path works without mDNS
